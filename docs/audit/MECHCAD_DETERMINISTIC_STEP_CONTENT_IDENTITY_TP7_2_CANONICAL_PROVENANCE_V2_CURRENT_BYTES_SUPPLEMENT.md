## Canonical CAD/M10 provenance @2 coverage

Two new tests in `tests/unit/test_candidate_provenance_artifacts.py` exercise the
existing `canonical-cad-provenance@2` and `canonical-m10-provenance@2` publication paths
using the accepted canonical mechanism@4, CAD realization@2, and M10 outcome@2 fixtures.
They publish typed envelopes, serialize/reparse the `*ProvenancePublication` wrappers,
create a fresh `CandidateProvenanceArtifactService`, and resolve the persisted records
through the canonical CAD/M10 V2 resolver branches. Assertions cover:

- exact declared envelope fields: CAD 3, M10 5, with no envelope self-hash;
- exact nested realization/outcome @2 schema literals and parent artifact/input-hash
  equalities;
- rejection of a canonical realization@1 inside provenance@2 and a canonical M10
  outcome@1 inside canonical M10 provenance@2;
- fresh-service resolution of canonical CAD@2, canonical M10@2, and the M10 envelope's
  canonical CAD@2 parent.

The test fixture uses the existing semantic STEP identity fixture and state-backed
revision/state hashes. Canonical M10 proof results are generated by the existing bounded
unit fixture application; these tests do not claim live provider, CAD, solver, or
structural execution.
