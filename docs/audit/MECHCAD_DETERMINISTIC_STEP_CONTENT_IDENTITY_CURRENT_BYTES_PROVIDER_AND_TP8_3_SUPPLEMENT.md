## `@3` bounded fixture migration blocker

The bounded test requests `DECLARED_BOUNDED_COLLISION_REPRESENTATION` for
`motor-mount` and `payload-body`. A non-live construction of the same candidate family
confirmed both are `component-specification@4` with non-null geometry sources (`ART-mount`
and `ART-body`). The current production semantic validator
`_validate_cad_inputs_v2` (`src/mechcad_harness/candidates/evaluation.py:593-610`)
requires every mapping for a source-backed specification to be
`TRUSTED_SOURCE_GEOMETRY` with the matching semantic identity and representation. A
bounded mapping for those unchanged source-backed specs would be rejected; dropping or
changing their source specification would alter the fixture engineering meaning.

`CandidateCadInstanceMappingV2` can structurally represent bounded fidelity, but the
accepted candidate/request validation chain cannot accept that fidelity for these
source-backed components. No test-family migration was applied because doing so while
preserving the required bounded semantics would require changing the production CAD
contract or the candidate specifications, both forbidden by this authorization.

Therefore the three-test `@3` migration is incomplete, the five-test aggregate was not
rerun on current bytes, and independent re-audit/final Epic acceptance remain blocked.
