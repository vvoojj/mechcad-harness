## Intended Scope

M1 changed `DesignState` from typed canonical state into persisted,
revisioned, integrity-bound canonical state:

```text
DesignState
    -> canonical JSON
    -> SHA-256 state hash
    -> immutable numbered revision snapshot
    -> current.json pointer
```

M1 is State Foundation, not a general execution framework.

## Actual Implementation

### State Persistence

`src/mechcad_harness/state/manager.py:StateManager` persists each project
beneath:

```text
<workspace>/projects/<project_id>/
  current.json
  revisions/
    REV-000001.json
    REV-000002.json
    ...
```

### Canonical Serialization and Identity

`src/mechcad_harness/state/hashing.py` hashes the complete JSON-mode
`DesignState` payload. Canonical JSON is UTF-8 with `ensure_ascii=False`,
sorted keys, compact separators, and JSON-native values. External records are
excluded because they are not `DesignState` fields, not because hashing removes
selected state fields.

`state_hash(...)` computes SHA-256 over the canonical JSON bytes and returns
`sha256:<hex digest>`.

### Revisions, Pointer, and Integrity

- Initial project state is revision `1`; subsequent revisions are monotonic.
- Snapshot paths are deterministic: `REV-{revision:06d}.json`.
- Existing revision snapshots cannot be overwritten.
- `current.json` contains project identity, revision, and state hash. It is a
  lightweight pointer and does not duplicate `DesignState`.
- Snapshot loading recomputes the canonical state hash and rejects mismatches.
- Pointer/snapshot hash mismatches are also rejected.
