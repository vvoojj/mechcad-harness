## M2 -> M3 Boundary

M3 changes `ChangeEngine.apply_proposal()` from returning a raw
`RevisionSnapshot` to returning an ephemeral `AppliedChangeResult` with:

```text
snapshot
changeset_id
changed_paths
```

The snapshot is the newly persisted canonical revision. The changeset ID comes
from the accepted in-memory `ChangeSet`. Changed paths come from operation
paths, with duplicates removed and first-occurrence order preserved. The result
is not persisted. M3 does not create revisions or directly mutate
`DesignState`.

There is no committed `DependencyService` directly consuming the result. A
caller explicitly maps it into `EvidenceStore.build_invalidation()` and
`EvidenceStore.record_invalidation()`.

## Committed Architecture

The main symbols are `AppliedChangeResult`, `DependencyGraph`,
`DependencyRule`, `DependencyEdge`, `ChangeImpact`, `InvalidationRecord`, and
`EvidenceStore`.

`ChangeImpact` contains `changed_paths`, `direct_nodes`, and `all_nodes`; there
is no separate `transitive_nodes` field. `all_nodes` includes direct and
downstream nodes. `InvalidationRecord.transitively_invalidated_nodes` is
populated from `all_nodes`, so it also includes direct nodes.

The graph uses literal segments, one-segment `*` wildcards, and prefix
matching. Direct and downstream impact is sorted and deduplicated. Cycles fail
closed with `DependencyCycleError`.

Invalidations and Evidence are external immutable JSON records:

```text
projects/<project_id>/invalidations/REV-XXXXXX.json
projects/<project_id>/evidence/<evidence_id>.json
```

Freshness is fail-closed. For Evidence at revision `N` and current revision
`M`, every invalidation record from `N+1` through `M` is required. Valid
provenance plus complete history and no matching later impact yields
`CURRENT`; a matching later impact yields `STALE`; missing history, invalid
provenance, or an unknown node yields `UNKNOWN`. `UNKNOWN` and `STALE` never
count as fresh.

Evidence remains outside canonical `DesignState`, is not automatically
deleted, and does not trigger recalculation.

## Deviations

- Planned `DependencyService` functions are embedded in `EvidenceStore`.
- The parser is a restricted local YAML/JSON parser rather than PyYAML.
- Duplicate configuration rules and edges are accepted rather than rejected
  by a dedicated duplicate-validation layer.
- The M2-to-M3 caller integration boundary lacks a direct committed assertion.

These are specification or test-coverage deviations, not absence of the M3
core capability.
